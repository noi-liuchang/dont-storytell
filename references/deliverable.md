# 叙事策略一页纸

交付让当事人作三个决定。押哪条有依据的判断，今天先做什么，出现什么结果要重想。读者还应看见这件事通往哪种未来，谁会有理由参与后续。

开头一段写当前处境、推荐的候选判断、一个值得追的未来与已有依据。不要把公司重新命名当作结论。接下来两三段按因果写剧情，每段让人看见现实变化和留下的能力、作品或关系，以及为什么有人愿意因此继续投入。段数不等于幕数。远期写条件，不安排保证成功的结局。收在第一次履约和关键改路信号。

读者需要逐项比较动作时，可在开头后用一张紧凑表，列“这一幕做什么 / 留下什么、谁接着投入 / 何时往前、何时改路”。不固定三幕，不把叙事拆成全是检查项的表格。默认连贯短稿，选择最容易理解本案的形式。

实际发生、当事人自述、顾问判断与设想分清。Vision 三个维度在同一个未来里相遇，缺证据的一角自然说明。角色的内心和对白必须有来处。真实取舍可以是先后次序、有限时间的分配或对旧承诺的保护，无须每案演一次拒绝诱惑。

材料薄时给候选页，允许只有第一段行动，写明它有可能打开什么后续。连判断都无法形成时交短诊断和一个关键问题。资料充分时不要让用户阅读四栏事实底稿、完整候选比较与全部案例检索。

中文正文通常控制在约 600–800 字，最终以实际版面为准。把第一次履约的细节集中在结尾，不在各段和结尾重复。导出时按正常可读字号核对一页是否放得下，溢出先合并重复判断、缩短说明，不能删掉关键依据和改路条件，也不要仅靠缩小字号挤入。长依据记录另留，不强装进正文。

初次使用见 [街区杂志完整示范](../examples/neighborhood-magazine.md)。示范包含输入、简短判断依据和用户实际收到的一页纸，表明格式与推演方式，不是已经实施的咨询成绩。需要找人物与切口时见 [咨询写法](consultation-craft.md)。

新一页使用 `schema: 3`。下面是虚构的社区电影院，示意格式、事实与设想的界线。

```json
{
  "schema": 3,
  "title": "星期二那场电影，由谁选？",
  "status": "虚构示意 · 候选",
  "opening": "在这个设定里，周二总有空座，却有几位常客每次散场还留下聊半小时。我愿意押这半小时：也许他们有一部想请街坊一起看的片子。",
  "passages": [
    {"text": "影院可以再降一次票价。也可以把一个平日夜场交给一位常客：由他选一部有放映权的片，写下为什么值得看，再自己请人来。片能不能放、场租能不能覆盖，还是影院要扛的账。"},
    {"heading": "第一次让出排片表", "text": "建议先排一晚。如果散场后有人接过下一场的选片权，这家店才有理由把周二留给街坊。不够付一晚成本，就先缩场次。"}
  ],
  "next": "约一位常客一起算一场电影的保本座位数，问他愿不愿意选第一部。"
}
```

必填 `title, status, opening, passages, next`。每段的 `text` 必填，`heading` 可省。 可选 `note` 是不抢正文的顾问校验，`sources` 是含 `label` 和可选 HTTP(S) `url` 的数组。私人原件可只标注可定位的名称。旧版 schema 1、2 及其五栏仍可正常渲染。
