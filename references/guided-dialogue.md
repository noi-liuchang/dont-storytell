# 可选模式 · 渐进对话

仅在用户主动选择引导，或信息过少且希望边谈边建模时启用。已收到材料、文件夹或明确的资料入口时，遵循主入口，直接出一页策略。以下延用 v0.2 的交互设计。依据用户在试用中的反馈：不愿被细枝末梢牵着走，希望像调用人物 Skill 一样容易进入，又能通过简单回答逐步形成策略。具体阶段、状态与问法是工程推演，不冒充作者原文框架。

引导时，先给对方看到一个可能的未来，再判断三者交集中哪一点需要本人回答。近处的动作和远处的条件一起交代；出现反例时允许重排故事序列。

## 1. 先给方向，再问一个关键问题

先利用当前对话、用户指定的材料和可用业务资料。已经给出的对象、经历、文章与选择不要重复索取。资料够了就做判断，不为了开启流程而提问。

引导起步时，用几句话交代：当前理解的商业命题、最终要形成什么、此刻最需要弄清什么。信息极少时把理解标为初步假设，不提前写一份完整定位。

一次只问一个核心问题，并让人能用口语回答。不要把“你想做什么、给谁、为什么、怎么赚钱”塞进一个问号。必要时解释回答将改变哪个判断。

例如，对“想做一个有叙事的专业服务品牌”，可先问“你做这门生意时，最想改变同行哪一种做法？”；已有完整服务资料时，应从具体矛盾问起。例句不是固定第一问。

## 2. 心中有整张图，嘴上只问当下的问题

维护一个随对话更新的工作模型，不逐项向用户展示空表：

| 需要理解的部分 | 它帮助决定什么 |
|---|---|
| 主体、阶段、实际生意、已有能力和决策范围 | 谁能承担哪种变化；当前适合多大承诺 |
| 外部变化、真实矛盾、主体在意的事 | 为什么值得做，为什么是现在 |
| 未来判断、受益者、成功的含义 | 要走向什么，而非只占哪个话题 |
| 产品、组织、收入、资源和合作的关系 | 判断会改变什么选择，哪里存在冲突 |
| 事实、承诺、反证与未知 | 哪些已经成立，哪些需要验证 |
| 参与者的利益和能动性 | 他为什么加入，加入后能改变什么 |
| 下一段行动、留下的积累与后续可能 | 如何活成这个主张，怎样持续发生 |

每项区分：用户已说明的事实、用户已作的选择、Agent 的候选解释、仍然未知。未知不是必须补齐的字段。

公司、产品、个人、社区或文化项目各有重心。个人的写作、视频、咨询、产品可能属于同一事业；先理解它们的关系，再判断是否需要内容规划。不要看到“IP”就自动转为粉丝画像和选题排期。

这张图留在本次对话内即可；除非用户要求保存，不自动建库、写文件或把私人资料转入公司空间。

## 3. 每轮都向前推进

收到回答后先更新理解，再选择下一步。一般只需一小段有判断的回应，随后一个问题；不机械复述整段回答，不每轮展示全表。

下一问优先解决：**答案不同，会使主张或真实选择明显不同的未知。** 找不到这种问题时，应先给判断或方案，不继续访谈。

- **用户说得短**：把它当压缩的经验。用上下文形成可修正解释，问仍然不明的决策；不要要求先补一份长文。
- **用户举人或公司为例**：提取例子在当前命题中的含义，继续处理用户自己的事业。不能凭一句欣赏就继承那个人的价值、商业模式或全部特征，也不展开人物百科问答。
- **用户表达抽象**：先给出有依据的解释或两三个可能含义，说明自己的倾向，让用户修正。避免把可兼容的价值强迫做二选一。
- **用户说“不知道”**：替他做一部分推演，给少量不同方向及各自代价，再问哪一点不符合实际。不要把原问题换个说法重问。
- **用户已有材料**：能读取就读，读后指出它如何改变判断。不能以找到了文章标题代替读正文；没读到时明确范围，继续不依赖它的部分。
- **用户纠正方向**：指出需要修改哪一层理解，并调整受影响的建议；保留仍成立的上下文，不从第一问重启。
- **用户质疑全局意识**：暂停细问，用已有材料给出商业命题、各部分的关系、关键冲突与当前建议；再处理最重要的未决项。

用户的信念、不可逆承诺与愿承担的关键代价由用户决定。结构整理、候选推演、材料归纳和一般执行选择由 Agent 承担。不要让用户代做框架设计。

## 4. 四个进展节点，不是四轮问答

| 进展 | 用户应得到什么 | 何时可以往前 |
|---|---|---|
| 看清处境 | “我们真正要解决的是这件事”及其关键矛盾 | 已能识别主体与改变的对象；未知可有条件保留 |
| 形成主张 | 一段候选判断：为什么值得做、走向哪里、与当前行为有何关系 | 已有来自经验的依据和方向；不要求先想出金句 |
| 落到取舍 | 产品、经营、组织或个人选择如何相互支持；最先要处理的冲突 | 已找到至少一个影响主张的真实选择与承担者 |
| 开始蓄势 | 下一段行动、会留下的积累、别人如何参与、何时修正 | 已能交付当前阶段可用的方案或条件方案 |

可以跳过已经清楚的节点，也可以因新事实回到前面。后半程不能长期停留在身份讨论；需要拿出可决策的方案。

在形成新判断或发生方向修正时，给一小段阶段工作稿，例如：“目前能确定的是……；我的初步判断是……；这意味着接下来要改变……；还会改变结论的一个问题是……。” 自然表述即可，不强制每次四栏。

让用户逐步看见方案长出来。关键假设尚未确定时可以提供候选，但不能把候选身份写成用户自述。给出建议不以反复问“要不要继续”收尾。

## 5. 收束成真实的叙事进程

当方向与关键选择足以支持行动，用 [交付骨架](deliverable.md) 形成当前初版，明确待验证部分。一次对话形成的是可用的判断与行动假设，不等于经营已经验证成功。

下一步要同时回答：

- 哪个现实状态会改变，谁能决定和承担？
- 做完后留下什么能力、关系、可信记录或可持续资源？
- 为什么这让下一件值得做的事变得更可能，其他人怎样参与？

规模与阶段相称。一个短动作也可以有积累；一套长期内容计划也可能没有积累。不要求所有对象都先创业、立刻变现或牺牲收入；检查其实际持续方式及消耗边界。

缺少关键立场时保留候选，不假装定案；缺少精确预算、排期等一般执行细节时，可提出有边界的建议，不因模板空栏无限访谈。用户要求“先给初版”时直接交付条件版。

## 6. 判断这次引导是否有效

看实际推进，而非问了几题：是否复用了已知内容；简单回答是否改变了判断；举例是否仍服务原商业命题；有没有把主张连接到经营选择与持续行动；用户是否已经拿到可修正的方案。必要时纠偏，不给用户做叙事成熟度考试。
